Agent config · device sync

Set it up once. Open it anywhere.

Your MCP servers, skills, agents and commands should live in one git repo, not in one machine's home folder. The device stops being the source of truth — it becomes a cache.

01 · The shape of the fix

Config flows through a repo, not through your memory

You edit on any device, push, and every other device is one pull behind. No re-setup, no drift.

Key property: OpenCode watches its config files. After a git pull the changes are live — no restart, no reinstall, no re-adding MCP servers by hand.

02 · What can and cannot travel

Split your setup into three buckets

Everything works once you accept that one bucket is portable, one is per-device, and one is deliberately never synced.

Travels in git

Deterministic, safe to commit, identical everywhere.

  • opencode.jsonc
    model, default agent, permissions, MCP definitions, skills sources
  • skills/
    SKILL.md folders + their scripts and references
  • agents/ · commands/
    subagents and slash commands
  • plugins/
    local plugin packages, if you keep any

Never sync

Device state and credentials. Syncing these causes bugs and leaks.

  • service.json
    background-service registration, per machine
  • ~/.local/share/opencode
    sessions, database, logs
  • API keys / tokens
    keep in env vars or a {file:} secret file
  • MCP OAuth tokens
    stored outside config; each device signs in once

Per-device, one-time

Unavoidable, but only once per machine — and never again after that.

  • Runtime installs
    npx / uvx / bunx MCP servers fetch themselves on first use
  • MCP OAuth sign-in
    /mcps → select server → authorize. Cached afterwards.
  • Provider auth
    whatever login your model provider needs

Free compatibility win

OpenCode also reads these global skill folders — so if hermes or Claude Code already uses them, both harnesses share one directory.

  • ~/.config/opencode/skills
    native global skills
  • ~/.claude/skills
    global compatibility path
  • ~/.agents/skills
    global compatibility path

03 · Pick your laziness level

Three ways to point a new device at the setup

Same repo underneath. Choose by how much you want to install on a fresh machine.

01

Clone the config directory

Repo is ~/.config/opencode. One git clone and you are done.

simplest · start here
02

Dotfiles repo + symlink

Keep one ~/dotfiles repo for everything; link agent-config/opencode into place. Skills can be shared by hermes, Claude Code, and OpenCode at once.

best if you sync more
03

HTTP skill catalog

Put an index.json on GitHub Pages and list the URL in skills. The device needs nothing but a URL — skills download and cache.

zero install · many machines

04 · The MCP reality check

MCP is 90% portable, 10% per-device — by design

Server definitions are just JSON. Secrets and OAuth tokens are deliberately kept out of your config, so they never reach git.

{
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp"   // travels
      },
      "company-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "headers": {
          "Authorization": "Bearer {env:MCP_API_KEY}"  // not the key itself
        }
      }
    }
  }
}

What a new device still needs

server defs100%
skills100%
secret valuesonce
OAuth loginonce

Secrets go in your shell profile, a {file:~/.secrets/x} path, or a password manager. OAuth credentials live outside config — sign in via /mcps once per device.

05 · The new-device ritual

One command, then one sign-in

This is the whole thing you repeat on a fresh machine. Everything else is automatic.

Clone the config into place

# Windows (PowerShell)
git clone git@github.com:YOU/agent-config.git "$env:USERPROFILE\.config\opencode"

# macOS / Linux
git clone git@github.com:YOU/agent-config.git ~/.config/opencode

Restore the one per-machine file

# back up before you clone, copy back after
Copy-Item "$env:USERPROFILE\.config\opencode\service.json" $env:TEMP\service.json

Sign in to OAuth MCPs — once

# inside OpenCode
/mcps   → select server → authorize in browser
opencode mcp list   → confirm "connected"
That's the whole gap. Everything you actually configured — servers, skills, agents, permissions, defaults — arrives with the clone. The only per-device cost is credentials you shouldn't be copying anyway.
